Lakukan tahap berikutnya pada project Ludo web yang sedang dibuat.

Jangan mengubah core game rules yang sudah ada. Fokus utama sekarang adalah membuat **gameplay terasa hidup, responsif, satisfying, dan seperti premium mobile board game** melalui:

* sound effects
* dice animation
* token animation
* turn feedback
* capture effects
* home effects
* win/lose animation
* UI feedback
* camera/board feedback
* bot presentation

Visual tetap menggunakan style:

**cute 3D cartoon board game**

dengan karakter original, toy-like world, glossy materials, rounded UI, soft lighting, colorful environment, dan polished mobile-game quality.

---

# 1. GAMEPLAY FEEDBACK SYSTEM

Buat satu sistem terpusat untuk gameplay effects.

Struktur:

```text
src/
├── game/
│   ├── engine/
│   ├── bot/
│   └── events/
│
├── audio/
│   ├── AudioManager.ts
│   ├── SoundEffect.ts
│   └── sounds/
│
├── effects/
│   ├── DiceEffect.ts
│   ├── TokenEffect.ts
│   ├── CaptureEffect.ts
│   ├── TurnEffect.ts
│   └── VictoryEffect.ts
│
└── components/
    └── game/
```

Game Engine tetap menjadi sumber kebenaran.

Effects hanya merespons event.

Jangan memasukkan visual animation logic ke dalam game rules.

Gunakan architecture:

```text
Game Engine
     ↓
Game Event
     ↓
Animation / Sound / UI Feedback
```

Contoh:

```text
ROLL_DICE
    ↓
DiceRolledEvent
    ↓
Dice Animation
    +
Dice Sound
```

# 31. GAME EVENT BUS

Jika belum ada, buat event system sederhana.

Contoh:

```ts
type GameEvent =
  | { type: 'DICE_ROLLED'; value: number }
  | { type: 'TOKEN_SELECTED'; tokenId: string }
  | { type: 'TOKEN_MOVED'; tokenId: string; steps: number }
  | { type: 'TOKEN_CAPTURED'; tokenId: string }
  | { type: 'TOKEN_ENTERED_HOME'; tokenId: string }
  | { type: 'TURN_CHANGED'; playerId: string }
  | { type: 'EXTRA_TURN'; playerId: string }
  | { type: 'GAME_WON'; playerId: string };
```

Effects subscribe ke event tersebut.

Contoh:

```text
DICE_ROLLED
 ├── Dice Animation
 ├── Dice Sound
 └── Result Feedback

TOKEN_CAPTURED
 ├── Capture Animation
 ├── Capture Sound
 └── Board Micro Shake
```

# 32. IMPORTANT: GAME LOGIC MUST STAY DETERMINISTIC

Animation tidak boleh menentukan game result.

SALAH:

```text
animation selesai
↓
baru menentukan token position
```

BENAR:

```text
Game Engine menentukan result
↓
state berubah
↓
animation menampilkan perubahan tersebut
```

Game state tetap menjadi source of truth.

# 40. ACCEPTANCE CRITERIA

Implementasi dianggap berhasil jika:

* Dice memiliki rolling animation.
* Dice berhenti pada hasil yang benar.
* Dice memiliki sound feedback.
* Roll 6 memiliki feedback khusus.
* Token tidak teleport saat bergerak.
* Token bergerak step-by-step.
* Token valid memiliki visual highlight.
* Token invalid tidak dapat dipilih.
* Capture memiliki animation dan sound.
* Token masuk HOME memiliki feedback.
* Pergantian turn memiliki feedback.
* Bot terlihat melakukan roll dan memilih token secara natural.
* Bot memiliki thinking delay.
* Player tidak dapat melakukan input saat animation berlangsung.
* Victory memiliki celebration.
* Defeat memiliki animation.
* Result reward memiliki animation.
* Play Again tidak reload browser.
* Audio dapat diaktifkan/dimatikan melalui Settings.
* Missing audio asset tidak menyebabkan crash.
* Tidak ada duplicate timers/listeners.
* Tidak ada console errors.
* Gameplay tetap responsive di desktop dan mobile.
* Core game logic tetap terpisah dari presentation.
* Animation tidak pernah mengubah hasil game secara langsung.
* Game Engine tetap menjadi source of truth.
