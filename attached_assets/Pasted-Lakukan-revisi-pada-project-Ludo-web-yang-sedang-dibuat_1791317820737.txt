Lakukan revisi pada project Ludo web yang sedang dibuat.

Pertahankan style visual **cute 3D cartoon board game**, dengan karakter original, toy-like environment, rounded UI, glossy material, soft shadows, dan kualitas seperti premium mobile game.

Namun sekarang lakukan perubahan besar pada **information architecture**.

# 6. BOT SYSTEM

Buat AI sederhana tetapi benar-benar dapat bermain.

Buat:

```text
src/game/bot/
├── BotPlayer.ts
├── BotStrategy.ts
└── BotDifficulty.ts
```

Bot harus:

1. menunggu gilirannya
2. melakukan roll dice
3. mendapatkan valid moves
4. memilih token
5. melakukan movement
6. melakukan capture jika tersedia
7. melanjutkan extra turn
8. menang jika semua token masuk HOME

Bot tidak boleh memanipulasi state secara langsung.

Bot harus menggunakan action yang sama seperti player:

```text
ROLL_DICE
SELECT_TOKEN
```

Dengan demikian:

```text
Human
   ↓
Game Engine

Bot
   ↓
Game Engine
```

keduanya menggunakan game engine yang sama.

---

# 7. BOT DECISION LOGIC

Jangan membuat bot benar-benar random.

Gunakan priority system.

Contoh:

```text
1. Move token yang bisa mencapai HOME
2. Capture opponent
3. Move token keluar dari YARD
4. Move token yang paling dekat HOME
5. Random legal move
```

Implementasikan fungsi:

```ts
chooseBestMove(
  gameState,
  validMoves
)
```

Bot tidak boleh memilih token yang invalid.

---

# 8. BOT DIFFICULTY

Buat tiga tingkat:

### EASY

Prioritas:

* mostly random legal move
* sedikit strategic decision

### NORMAL

Prioritas:

* HOME
* capture
* exit yard
* progress

### HARD

Prioritas:

* HOME
* capture
* avoid dangerous positions
* maximize progress
* pilih move berdasarkan evaluasi board

Untuk tahap awal, **EASY dan NORMAL wajib bekerja**.

HARD dapat menggunakan strategy yang lebih sederhana terlebih dahulu, tetapi architecture harus sudah mendukung difficulty.

---

# 9. BOT THINKING DELAY

Jangan membuat bot bergerak langsung.

Setelah dice:

```text
Bot rolls
   ↓
500-1000ms thinking
   ↓
highlight selected token
   ↓
move token
```

Tambahkan sedikit variasi delay agar tidak terasa seperti script instan.

Jangan menggunakan delay sebagai bagian dari game rules.

Delay hanya bagian dari presentation layer.

# 19. GAME STATE

Pastikan game state dapat mengakomodasi:

```ts
type PlayerType =
  | 'human'
  | 'bot';

type PlayerState = {
  id: string;
  type: PlayerType;
  name: string;
  color: PlayerColor;
  tokens: TokenState[];
};
```

Bot harus menjadi player biasa dari perspektif Game Engine.

Perbedaan hanya pada siapa yang menghasilkan action:

```text
Human Input
       ↓
Game Action

atau

Bot Strategy
       ↓
Game Action
```

# 25. ACCEPTANCE CRITERIA

Revisi dianggap berhasil jika:

* Home jauh lebih clean.
* Daily Bonus tidak muncul di Home.
* Missions tidak muncul di Home.
* Shop tidak muncul di Home.
* Friends list tidak muncul di Home.
* Reward Track tidak muncul di Home.
* Semua fitur tersebut tetap dapat diakses melalui menu.
* Play menu tersedia.
* VS BOT tersedia.
* Bot dapat memainkan game dari awal sampai selesai.
* Bot menggunakan Game Engine yang sama dengan player.
* Bot hanya memilih valid moves.
* Bot dapat mendapatkan extra turn.
* Bot dapat melakukan capture.
* Bot dapat mencapai HOME.
* Bot dapat menang.
* Result Screen muncul.
* Play Again berfungsi.
* Tidak ada console errors.
* Tidak ada horizontal overflow.
* Desktop dan mobile tetap responsive.
